1. Project Structure

LoanFlow is a decoupled single-page application (React 19 + Vite) fronting a TypeScript/Express API. The two are independent npm projects (not a workspace monorepo) sharing only conventions and the Prisma schema contract.

2. Database & Data Model

PostgreSQL 16 accessed via Prisma 5. Five core models support identity, sessions, OTP, audit, and documents. The schema is the source of truth; however, the Document model is applied via prisma db push at container start rather than a versioned migration (see Gap #4).

Access patterns

  • Documents: scoped by userId + optional category filter; soft-delete via status='DELETED'; indexed on userId and applicationId.
  • Object key convention: borrowers/{userId}/applications/{applicationId}/documents/{category}/{documentId}/{fileName} (sanitized path segments, prefix-guarded so a user cannot escape their root).
  • No pagination on document listing — full list returned per user.

3. UI, UX & Backend Design

Frontend UX

  • Shell: Workspace.tsx — fixed sidebar + topbar (breadcrumb, search, "New application") + <Outlet/>; mobile drawer + bottom nav.
  • Design system: shadcn/ui (slate) + Tailwind tokens in index.css (:root light, .dark dark), Inter font, cn() helper, ToastProvider (success/info/error).
  • Document upload UX: "Upload to" single-category pills, drag/drop FileDropzone, per-file progress + multipart part counter, duplicate guard (name+size) against vault, checklist filter pills, auto-filter to uploaded category, "X of N categories have files" status, bulk delete.
  • Inter-view comms: DOM custom events document:uploaded / document:deleted (decoupled refresh).
  • State: React Context (AuthProvider) + local useState; no global store. Tokens in localStorage.

Backend behavior

  • Auth: stateless JWT access (15m) + DB-backed refresh session (7d, rotated). Account lockout after 5 fails (+15m). OTP (SHA-256 hashed, 60s TTL, rate-limited).
  • Upload: server issues presigned URL (≤100MB single PUT; >100MB multipart, 64MB parts, concurrency 4). Client PUTs to S3 directly; complete does HeadObject then creates Document.
  • Storage: cached S3 client, forcePathStyle (MinIO), WHEN_REQUIRED checksum, bucket bootstrap (CORS, lifecycle abort of stale multipart at 7d).
  • Email: Brevo REST (4-retry backoff) for OTP, reset, welcome, login-notification, password-changed. No-op provider in dev without Brevo.
  • Cross-cutting: Helmet CSP, input sanitization, per-endpoint rate limiting, Pino JSON logs, audit trail for auth + document events.

4. Overall System Architecture

The platform runs as three Render web services plus a managed PostgreSQL, with S3-compatible MinIO for object storage and Brevo for transactional email/SMS. The browser talks only to the Express API; large files bypass the app server and go straight to object storage via presigned URLs.

5. Gap Analysis & Recommendations

Findings from a full code review, prioritized by enterprise-readiness impact. Severity reflects security, compliance, and deployability risk.

#SevFindingRecommendation
1CriticalBackend throws on boot if Brevo is not configured in production (email.service.ts); BREVO_API_KEY is absent from render.yaml.Add BREVO_API_KEY as a secret on Render, or make email best-effort (don't crash boot) and queue notifications.
2CriticalDatabase credentials are committed in plaintext in render.yaml (and MinIO defaults minioadmin/minioadmin).Move all secrets to Render secret store (sync:false); rotate DB + MinIO credentials; purge from git history.
3HighRBAC is decorative — requireRole exists but no route enforces ADMIN/ANALYST/APPROVER.Wire requireRole into protected endpoints and ProtectedRoute allowedRoles on the frontend, or formally scope to BORROWER-only for now.
4HighPrisma drift: Document + DocumentStatus are not in 01_init; no migration_lock.toml; prod relies on db push.Generate a real migration (Document + enum) and commit migration_lock.toml, or formally adopt db push with documented process.
5HighFrontend VITE_API_URL points to arogan-mx0n.onrender.com while backend/CORS use loanflow-* hostnames — likely broken API/CORS in prod.Reconcile URLs; drive VITE_API_URL and CORS_ORIGIN from a single source; verify against live service names.
6HighNo document verification / malware-scan pipeline; VERIFIED/PENDING never written. Compliance gap for a loan/financial app.Add a scan/verification stage (async job or AV service) that transitions UPLOADED → VERIFIED before analyst review.
7MediumNo CI/CD — no lint/typecheck/test gate; blind autoDeploy ships broken builds.Add a GitHub Actions workflow (lint + typecheck + jest + build) and protect the branch or disable autoDeploy.
8MediumNo cache/queue/Redis; rate-limiting, sessions, and cleanup are per-instance in-memory — breaks under horizontal scaling.Introduce Redis for shared rate-limit/cleanup state if scaling beyond a single instance.
9MediumUnbounded AuditLog with no retention; cleanup.service only prunes sessions/OTPs.Add an AuditLog retention/archive job and a TTL policy.
10LowDuplicate guard is name+size only (same content, different name/size bypasses it).Consider content hash (ETag/checksum) comparison for stronger de-duplication.
11LowOTP TTL = 60s (very tight); SMS text hardcodes "60 seconds" regardless of config.Raise TTL to 5–10 min and read the value from config in templates.
12LowSeveral hardcoded values: applicationId='LAP-2026-0184', mock-only Dashboard/Applications, text-success-500 not in Tailwind, inconsistent delete-confirm (modal vs window.confirm).Parameterize application context; wire Dashboard/Applications to live APIs; standardize tokens and a single DeleteConfirmDialog.
13Lownodemailer unused dependency; minor dead code (generateRefreshToken, logAudit).Remove unused deps/code; keeps the supply surface small.
14LowE2E specs contain real-looking credentials in source.Move test credentials to env vars / secrets; never commit real passwords.

7. Roadmap to Enterprise Readiness

Phase 0 — Stabilize (days)

  • Rotate & externalize all secrets (DB, MinIO, Brevo).
  • Add BREVO_API_KEY to Render; verify boot.
  • Reconcile VITE_API_URL / CORS_ORIGIN.
  • Generate the missing Document migration + lock file.

Phase 1 — Harden (weeks)

  • Add CI gate (lint/typecheck/test) + protected branch.
  • Enforce RBAC on routes and frontend guards.
  • Add document scan/verification pipeline (UPLOADED → VERIFIED).
  • Introduce AuditLog retention + pagination.
What is solid today: layered backend, defense-in-depth middleware (Helmet/CSP, CORS, sanitization, rate limiting, bcrypt, JWT rotation, lockout, audit), clean S3 presigned-upload pattern, a polished, modular Borrower Workspace UI, and strong unit + e2e test coverage.
