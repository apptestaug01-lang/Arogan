S3 Document Vault — Frontend/UI Implementation Plan

Companion to docs/s3-document-upload-plan.html. Backend chunks A–E are merged to main. This document plans the remaining frontend wiring so the existing (real) explorer + viewer render live data, and designs the missing screens. All UX reuses the existing mock-up design system — no new color palette, no invented primitives.

Design system (grounded, not hallucinated): tokens page-eyebrow / page-title / page-sub; primitives Card, CardHeader, CardTitle, CardContent, CardDescription, CardFooter (components/ui/card.tsx); Button (variants default/outline/ghost/destructive/link, sizes default/sm/lg/icon); Input; SectionRow (components/workspace/SectionRow.tsx) for checklist rows; icons from lucide-react (Folder, File, UploadCloud, X, ChevronLeft, ChevronRight, Download, Trash2, Paperclip, CheckCircle2); layout grid gap-6 lg:grid-cols-[1fr_300px]; status color text-emerald-600 for "Complete". There is NO Dialog/Modal primitive in the UI lib — modals are built as a fixed overlay + Card. Current "Required documents" list is mock data from @/mock/workspace and must be replaced by real document records.

  • Icons only from lucide-react (Folder, File, UploadCloud, X, ChevronLeft/Right, Download, Trash2, Paperclip, CheckCircle2).

  • VaultPicker and form-chip are blocked until a form / DocumentLink schema exists (out of scope of chunks A–E).
