Document Extraction Flow

RECOMMENDED

Files are stored in S3, picked up for batch extraction after all uploads complete, converted to structured JSON, and stored in the database.

Architecture Summary

Raw binaries live in object storage (Backblaze B2 / S3). Only the extracted, structured JSON — fields, pages, rawText, documentType — is stored in PostgreSQL. The extraction pipeline fetches documents from S3 (not from an upload request body) and writes results to the DocumentExtraction table.

Step-by-Step Flow

  1. Upload files via presigned URLs
    Client requests a presigned PUT URL from the backend POST /api/documents/presign. Upload goes directly Client → B2. No backend streaming. Backend: document.service.ts:30
  2. Complete upload — register metadata in DB
    Client calls POST /api/documents/{documentId}/complete. Backend verifies object exists (headObject), creates a Document record (points to S3 key), and triggers per-doc extraction. Backend: document.service.ts:68
  3. Batch extraction (after all uploads)
    When all documents are uploaded, the frontend calls POST /:applicationId/extract-all. This processes all documents for the application at once via ExtractionPipeline.processMany() with 4-way concurrency. Backend: autoFillRoutes.ts:13, autoFillService.ts:79
  4. Pipeline picks each document from S3
    The pipeline iterates over uploaded documents, reads each S3 key from the DB Document record, and issues a GetObjectCommand to fetch the file content into a Buffer. Backend: extractionPipeline.ts:175
  5. Convert to structured data
    Format-specific parsers parse the binary:
    • PDF → pdf-parse + Tesseract OCR → text + pages
    • Images → Tesseract OCR → text
    • DOC/DOCX → mammoth → HTML/text
    • XLSX → xlsx lib → rows/tables
    • CSV → plain text
    Documents ≤ 10 MB; larger files skip extraction.
  6. Extract fields (regex + LLM)
    Each document is classified by type (PAN_CARD, BANK_STATEMENT, etc.). Type-specific regex extractors run first, then an LLM extractor. Results are merged by confidence. Backend: extractionPipeline.ts:223-266
  7. Store JSON result in DB
    Merged fields, raw text, page data, document type, and model used are persisted in DocumentExtraction table: fields (Json), pages (Json), rawText (Text), documentType, status. Backend: schema.prisma:106
  8. Autofill forms from DB
    The AutoFillService reads extracted fields from the DB, maps them to wizard steps (kyc, business, financials, loan), and returns pre-filled form data. Cached results are served without re-extraction. Backend: autoFillService.ts:36

Batch Conversion Utility

A standalone CLI utility (backend/src/scripts/batchConvertDocuments.ts) reads documents from the S3/B2 bucket, lossless converts them to structured JSON, and writes the JSON back to the same bucket as {originalName}.json.

Usage

cd backend
# Preview what would be converted (no writes)
npm run convert:dry-run

# Convert all documents in the bucket
npm run convert:all

# Convert only documents under a prefix
npm run convert:all -- --prefix "borrowers/user123/"

# Force re-convert everything (overwrite existing JSON)
npm run convert:all -- --force

# Limit to first 10 documents
npm run convert:all -- --limit 10

# Convert only PDFs
npm run convert:all -- --contentType "application/pdf"

CLI Flags

FlagDefaultDescription
--prefix(root)Only process objects under this S3 key prefix
--forcefalseOverwrite existing .json files (skip if already exists)
--dry-runfalseLog what would happen without writing JSON
--concurrency3Number of parallel workers
--limit(all)Maximum number of documents to process
--contentType(all supported)Only process documents of this MIME type

Lossless JSON Structure

Each converted JSON preserves all data from the source document — not just extracted fields. The converter module is at backend/src/utils/documentConverter.ts.

Idempotency & Resumability

  • If {originalName}.json already exists in the bucket, the document is skipped (use --force to override).
  • JSON output includes Metadata headers on the S3 object pointing back to the source key, content type, size, and checksum — so you can verify the JSON matches its source.
  • Documents larger than 100 MB are skipped (the converter loads the full file into memory for parsing).
  • Files that fail conversion (unsupported format, OCR unavailable) get a jsonFile with an error field describing the issue, so you can retry later.
