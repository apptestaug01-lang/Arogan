Document → Application Auto-Fill

Automatically extract the 15 LoanFlow application fields from the documents already stored in the S3 vault, so a borrower can start a New Application without manual data entry. Modular, client-side, and source-attributed.

1. Goal & principles

  • Zero manual entry: a single “Auto-fill from documents” action reads the vault and prefills the form.
  • Exact-meaning matching: each field has its own extraction strategies (context keywords + regex) and a ranked category affinity (which vault doc types are most likely to contain it).
  • Source-attributed: every value carries the document + snippet it came from, shown in a review panel so the user verifies before applying.
  • Modular & offline: a self-contained utility with no backend/LLM keys required; an LlmFieldExtractor adapter is a clean drop-in extension point.
  • Main stays clean: built in reviewable chunks, each merged via squash PR.

5. Confidence & provenance

Every ExtractedField carries value, a confidence of high (strong pattern + context keyword) / medium (pattern only) / low, and a source with the originating document name + the matched snippet. The review panel renders these so the borrower confirms before “Apply”. Fields with no match are listed as missing and left blank for manual entry.

6. Extension point (optional LLM)

extractApplication.ts accepts an optional fieldExtractor. A future LlmFieldExtractor can call a backend structured-extraction endpoint (Azure AI / OpenAI function-calling) and return the same ExtractedField shape, falling back to heuristics when unavailable. No change to the UI or the field definitions is required.
